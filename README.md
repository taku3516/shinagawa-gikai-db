# 品川区議会DB

品川区議会の公式情報を基に、住民が読みやすい形に整理したページです。

- **サイト名**: 品川区議会DB
- **対象**: 平成13年〜令和8年（26年分）の品川区議会日程・議案・質問・会議録
- **免責**: これは品川区が運営しているものではありません。正確な議決結果・日程・資料は必ず[品川区議会公式サイト](https://gikai.city.shinagawa.tokyo.jp/)を確認してください。

## 機能

- 📅 **年間の流れ** — 定例会・臨時会・月例委員会をカード形式で表示
- 📝 **会議の詳細** — 日付ごとの出来事、公式資料・録画・議事録へのリンク
- 🧭 **会議ワンストップ** — 年と会議を選ぶと、日程・議案・請願陳情・質問答弁・委員会質疑・録画・会議録を1ページに集約
- 🎥 **録画と質問・答弁の連結** — 質問・答弁要約の直後から、その質問者または会議の公式録画へ移動
- 🗳️ **議案・請願・陳情** — 平成30年〜令和8年は公式ページの掲載分を全件収録（平成13〜29年は未収録。収集手順は[実装準備・監査手順](docs/history-expansion.md)を参照）
- 📨 **請願・陳情を1件ずつ追う** — 平成27年〜令和8年を受理番号で名寄せし、付託委員会・受理年月日・議決結果に加えて、継続審査で定例会をまたいだ経過と委員会でどう審査されたかを案件ごとのページで表示
- 💬 **代表質問・一般質問** — 平成13年〜令和8年の全26年で全発言項目を掲載し、取り下げを除いて会議録からの質問・答弁要約を収録
- 🏛️ **委員会質疑** — 平成13年〜令和8年の常任・特別・議会運営委員会について会議日ごとに出典（正式会議録／校正原稿）付きで収録
- ↕️ **段階的な開閉** — 会議、資料種別、質問者ごとに情報量を調整
- 📖 **会議録** — 正式版への案内と校正原稿PDF一覧
- 📜 **意見書・決議等** — 公式掲載の意見書・決議・要望書・抗議文等を年・種類・キーワードで検索
- 👥 **議員・政治家名簿** — 現職・元職の区議、都議、衆議、区長を8区分で切り替えて表示
- 🗳️ **選挙アーカイブ** — 1997年以降の区議選・区長選・都議選の結果を候補者・得票数つきで収録（衆議院選は参考サイトのみ）
- 💴 **政務活動費** — 令和7〜3年度の収支一覧と、会派・議員別の活動概要・収支報告書を年度別に掲載
- 📊 **行政評価** — 事務事業評価・政策評価を年度別に掲載し、評価区分（拡大・継続・改善・廃止）で色分け
- 📰 **品川区ニュース** — RSSと公式サイトの新着一覧から地域ニュースを自動収集し、検索・タグ絞り込み・端末内保存に対応。任意ログインによる端末間同期の枠組みも用意
- 🗺️ **町会・自治会区域検索** — 公式境界を淡い4色で塗り分け、町会名・住所・地域区分・町会長・連絡先・紹介・活動から検索。端末内だけでGPS現在地を表示
- 🔍 **横断検索** — 議会・人物・選挙・政務活動費・ニュースなどを年をまたいでまとめて検索。年データは表示後に順次読み込み、初期表示を軽量化
- 🔗 **参照元** — 議会情報は品川区議会公式3ドメイン、ニュースは各記事に発信元リンクを併記
- 📱 **スマートフォン対応** — 全ページを幅320px以上で横スクロールなしに表示。ナビゲーションは折りたたみメニューにまとめ、ボタン・リンクは指で押しやすい大きさ（44px以上）を確保
- ♿ **アクセシビリティ設定** — 全ページ共通で文字サイズ、高コントラスト、動きを減らす設定を選択し、端末内に保存

## スマートフォンでの表示

- 全11ページを幅320px〜1440pxで確認し、横方向のはみ出しが出ないようにしています
- 画面幅640px以下では、共通ナビゲーション（14個のリンク）が「☰ メニュー」に折りたたまれ、現在表示中のページ名がボタンに表示されます。タップすると縦一列で開きます
- 入力欄・選択欄の文字は16px以上にして、iOSで触れたときに画面が自動拡大しないようにしています
- 選挙結果など横に長い表は、表の上に「← 表は横にスクロールできます →」と案内を出したうえで、表だけを横スクロールできるようにしています
- パソコンでの表示は変更していません（折りたたみメニューは640px以下でのみ現れます）

## 技術スタック

- HTML/CSS/JavaScript のみ（フレームワーク・ビルド不要）
- データは `data/*.js` に分離（`window.SHINAGAWA_DB` に登録するスクリプト形式）
- `site-nav.css` / `site-nav.js` — 全ページ共通のナビゲーション（スマートフォンでは折りたたみメニュー）
- `site-mobile.css` — 全ページ共通のスマートフォン向け調整（タップ領域・入力欄の文字サイズ・表の横スクロール）
- `site-a11y.css` / `site-a11y.js` — 全ページ共通の表示設定、本文スキップリンク、設定の端末内保存
- `data/site.js` — 共通設定と年の一覧（各ページはこの `years` を見て年データを読み込む）
- `data/members.js` / `data/former-members.js` — 現職・元職の区議名簿データ
- `data/politicians.js` — 現職・元職の都議、衆議、区長名簿データ
- `data/people.js` — 質問者と議員を紐付けるための人物台帳（表記揺れの名寄せ用）
- `data/petitions.js` — 請願・陳情を受理番号で名寄せした台帳（自動生成）
- `data/petitions-official.js` — 公式の請願・陳情ページから取得した付託委員会・受理年月日・議決結果（自動生成）
- `data/resolutions.js` — 品川区議会公式「意見書・決議等」から取得した意見書・決議等（自動生成）
- `data/elections.js` — 品川区の選挙アーカイブデータ
- `data/seimu.js` — 政務活動費の年度・会派・議員別公式資料（自動生成）
- `data/seijishikin.js` — 政治団体の収支報告書データ
- `data/fiscal.js` — 予算・決算の年度別公式資料
- `data/gyosei.js` — 行政評価（事務事業評価・政策評価）の年度別公式資料
- `data/news-items.js` — 収集済みニュース（自動生成）
- `data/chokai.js` — 13地域センターの町会・自治会名と住所区域（自動生成）
- `data/chokai-boundaries.js` — 品川区「しながわMAP」公式Shapeから変換した町会境界GeoJSON（自動生成）
- `data/chokai-profiles.js` — 連合会・しながわすまいるネットの町会長、連絡先、紹介、活動、ウェブサイト・SNS（自動生成）
- `data/h13.js`〜`data/h29.js` — 平成13〜29年の基礎データ（会議・質問・答弁要約。議案・請願陳情は未収録）
- `data/h30.js`〜`data/r08.js` / 各 `-complete.js` — 平成30年〜令和8年の基礎データと全件表示用補足データ
- `data/h13-committees.js`〜`data/r08-committees.js`（および分割ファイル `-part-NN.js`） — 年度別の委員会質疑・答弁要約

過去年の委員会データを更新する場合は `python3 scripts/prepare_committees.py --year <西暦年>` で再生成できます。
会議録の取得には poppler（`pdfinfo` / `pdftotext`）が必要です（Ubuntu/Debianは `sudo apt-get install poppler-utils`、macOSは `brew install poppler`）。
開発環境から会議録へ到達できない場合は、GitHub Actionsの「委員会質疑を会議録から作り直す」を年を指定して手動実行してください（`.github/workflows/rebuild-committees.yml`）。
poppler と依存ライブラリの用意から、要約の検査、更新の保存までを通しで行います。

自動更新のワークフローは、生成に時間がかかる間に main が進んでいても成果を落とさないよう、
保存を `scripts/commit_data_update.sh` に任せています（拒否されたら取り直して積み直す）。

本会議（平成年）の質問・答弁要約は `python3 scripts/build_heisei_year.py <平成の年>` で再生成します。
こちらも GitHub Actions の「本会議の質問・答弁を会議録から作り直す」で手動実行できます
（`.github/workflows/rebuild-plenary.yml`）。**委員会は西暦、本会議は平成年**を指定する点に注意してください。

## 質問・答弁要約の品質

本会議の代表・一般質問と委員会質疑の要約は、「何について質問したか」「何について答弁したか」が
読み取れることを条件にしています。判定と整形は `scripts/qa_summary.py` に集約し、生成・修復・検査が
同じ定義を使います。書き方のルールは[要約作成ルール](docs/qa-summary-rules.md)にまとめています。

```bash
python3 scripts/check_qa_summaries.py           # 検査（要修正が1件でもあれば終了コード1）
python3 scripts/check_qa_summaries.py --details # 問題のある要約も表示
python3 scripts/repair_qa_summaries.py --write  # 機械的に直せるものを修復
```

`.github/workflows/check-qa-summaries.yml` により、`data/` や要約スクリプトを変更するたびに
自動で検査されます。文の途中で切れている、答弁が古い文言のまま、といった機械的に直せる問題が
あると失敗します。会議録から取り直さないと直らない項目は件数を出すだけで、再生成のたびに減らします。

平成30年〜令和7年の全件化と会議録要約、および平成13〜29年に議案・請願陳情を追加する手順は、[実装準備・監査手順](docs/history-expansion.md)にまとめています。質問・答弁要約の書き方は[要約作成ルール](docs/qa-summary-rules.md)にまとめています。平成13〜29年の議案・請願陳情は、公式サイトへ到達できる環境で次を実行すると収集できます。

```bash
python3 scripts/build_heisei_year.py 20   # 平成20年を再生成
```

## 品川区ニュースの自動収集

- `news.html` — ニュース一覧、タグ検索、保存済みニュースの表示
- `data/news-sources.json` — 地域語・タグ規則・RSS・RSSのない公式サイトの設定
- `data/news-items.js` — 収集済みニュース（自動生成）
- `scripts/collect_news.py` — RSSと公開Webページの収集、重複排除、関連度判定、タグ付け
- `.github/workflows/collect-news.yml` — GitHub Actionsで毎時00分に確認し、記事に変更がある場合だけ収集結果を保存
- `news-sync.js` / `data/firebase-config.js` — 希望者だけがGoogleログインで保存内容を同期する機能（公開版では無効）
- `firebase/firestore.rules` — 利用者本人の同期領域だけを許可するデータベースルール

ローカルで収集を試す場合は、追加ライブラリなしで次を実行できます。

```bash
python3 scripts/collect_news.py
```

記事本文の転載を避けるため、保存する概要は最大240文字です。東京都公式RSSは再配信を伴う利用に事前申請が必要なため、設定には登録していますが無効にしています。

任意ログイン・同期を有効にする場合は、[Firebase同期の設定手順](docs/firebase-sync-setup.md)に沿って所有者設定を行います。未設定のままでもニュースページは従来どおり動作します。

## 請願・陳情データの更新

`seigan.html` は、年データ（`data/h30.js`〜`data/r08.js` と `data/*-complete.js`）に入っている定例会ごとの
請願・陳情を、受理番号（例：令和5年陳情第31号）で名寄せした `data/petitions.js` を読みます。年データや
委員会データを更新したら、次のコマンドで台帳を作り直します（外部サイトへは接続しません）。

```bash
python3 scripts/prepare_petitions.py
```

- 継続審査で複数の定例会にまたがる案件は1件にまとめ、定例会ごとの議決結果を審査経過として並べます
- 委員会会議録（`data/*-committees-part-*.js`）の議題名に受理番号が現れるものを、委員会審査として紐付けます
- 公式ページの取り込み時に受理番号の列がずれている行（平成30年・令和元年の一部）は、番号として読み直したうえで
  議決結果を「未収録」として扱います。受理年は委員会会議録の議題名と件名が一致する場合だけ補い、確定できないものは
  未確定のまま掲載します（推測での補完はしません）
- 収録件数・未確定の案件・取り込めなかった行は [請願・陳情データの収録状況](docs/petition-inventory.md) に記録されます

### 公式ページからの取得

付託委員会・受理年月日・議決結果などは公式の[請願・陳情の審議状況](https://gikai.city.shinagawa.tokyo.jp/katsudou/petition)にしか載っていないため、
`scripts/fetch_petitions.py` で年ごとのページ（平成27年〜令和8年）から取得し、`data/petitions-official.js` に保存します。

- `.github/workflows/collect-petitions.yml` — 毎週月曜（日本時間 朝5時）に取得し、更新があれば保存
- 手動実行では `mode` を選べます。`write` は取得して保存、`inspect` はページ構造を実行ログへ書き出すだけ（公式ページの作りが変わったときの調査用）
- 公式ページの表は年によって作りが違います（令和元年以降は「委員会審査」「本会議結果」の2列、平成31年以前は「結果」の1列）。両方に対応しています
- 備考が「〇〇委員会へ参考送付」の案件は、付託も議決もされていないため結果は空のままです

開発環境から公式サイトへ到達できる場合は、手元でも実行できます。

```bash
python3 scripts/fetch_petitions.py --write     # 取得して data/petitions-official.js を更新
python3 scripts/fetch_petitions.py --inspect   # ページ構造だけを確認する
python3 scripts/prepare_petitions.py           # 年データと突き合わせて data/petitions.js を作り直す
```

## 町会・自治会データの更新

`chokai-map.html` は、東京都・品川区の町会一覧と住所区域、公式Shape境界、品川区町会自治会連合会としながわすまいるネットの公開プロフィールを表示します。公式情報を再取得する場合は次を実行します。

```bash
python3 scripts/prepare_chokai.py
python3 scripts/prepare_chokai_boundaries.py
python3 scripts/prepare_chokai_profiles.py
python3 scripts/export_chokai_kml.py
```

GitHub Actionsでも毎週確認し、変更がある場合だけ自動保存します。プロフィール取得は各サイトの公開条件に従い、ためまっぷの詳細ページを60秒間隔で取得します。公開されていない項目は推測せず、空欄のまま掲載しません。

Googleマイマップでは「レイヤを追加」→「インポート」から `exports/shinagawa-chokai-map.kml` を選択してください。町会・自治会区域を淡い4色で表示し、町会名、地域区分、住所区域、公開されている町会長・連絡先・紹介・ウェブサイト・SNS・出典を各区域の属性として取り込めます。

## 使い方

### ローカルで開く

`index.html` をダブルクリックしてブラウザで開くだけです。

HTTPサーバー経由で確認したい場合は次でも開けます：

```bash
cd shinagawa-gikai-db
python3 -m http.server 8000
```

### 過去年・未来年のデータを追加

1. `data/r09.js` など新しい年のファイルを作成（`data/r08.js` と同じ形式。冒頭の登録先を `window.SHINAGAWA_DB.years["r09"]` にする）
2. `data/site.js` の `years` 配列へ追加し、`available` を `true` にする

`data/site.js` の `years` は、会議録ページ（`kaigiroku.html`）と横断検索（`kensaku.html`）が年データを読み込む際の一覧を兼ねています。ここに追加すれば両方のページが自動で新しい年を扱います。

例：
```json
{
  "id": "r09",
  "label": "令和9年",
  "file": "data/r09.js",
  "available": true
}
```

## データ設計

### リンクの色分け

- **青（official）** — 公式資料・日程ページ
- **赤（video）** — 録画中継ページ
- **緑（minutes / minutesDraft）** — 会議録検索 or 校正原稿PDF

### リンク型の説明

| 型 | 用途 |
|---|---|
| `official` | 公式資料・日程へのリンク |
| `video` | インターネット中継の録画へのリンク |
| `minutes` | 会議録検索システム（正式版）へのリンク |
| `minutesDraft` | 校正原稿PDF（※正式版公開後に削除される） |

校正原稿PDF型のリンクが含まれる場合、自動で「削除される場合の対策」の案内が表示されます。
