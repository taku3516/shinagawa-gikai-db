# サイトとデータの構成

品川区議会DBのページ、共通ファイル、データ形式、表示上の設計をまとめます。データの取得・再生成方法は[データの更新方法](data-maintenance.md)、GitHub Actionsの動作は[自動更新とGitHub Actions](automation.md)を参照してください。

## 技術構成

- HTML / CSS / JavaScriptのみで動作し、フレームワークやビルドは不要です。
- データは`data/*.js`に分離し、`window.SHINAGAWA_DB`へ登録するスクリプト形式です。
- `index.html`を直接開く場合と、GitHub PagesなどのHTTPサーバーから開く場合の両方に対応します。

## 共通表示ファイル

読み込む順番が意味を持ちます。各ページの`<style>`は最後に来るので、
どうしても個別に変えたいページだけが上書きできる形にしてあります。

    site-theme.css → site-base.css → site-nav.css → site-controls.css
                   → site-mobile.css → site-a11y.css → ページの <style>

- `site-theme.css` — 配色とデザイントークン。デジタル庁デザインシステムの値をそのまま使います。文字サイズの倍率`--fs`と、高コントラスト時の色の差し替えもここです。
- `site-base.css` — ページの骨格（`body`、`.container`、`h1`、`.lead`、`.hero`、`footer`、リンクなど）。以前はこれらが15ページに散らばって少しずつ違う値になっていたので、1か所にまとめました。
- `site-nav.css` / `site-nav.js` — 全ページ共通のナビゲーション。役割で4群に分け、現在地は下線で示します。スマートフォンでは折りたたみます。
- `site-controls.css` — 切り替えUIの語彙。囲みの有無が意味を持ちます。
- `site-mobile.css` — タップ領域、入力欄の文字サイズ、表の横スクロールなど、スマートフォン向けの共通調整です。
- `site-a11y.css` / `site-a11y.js` — 文字サイズ、高コントラスト、動きを減らす設定、本文スキップリンク、端末内への設定保存を扱います。

### 守っている約束

- **枠の有無で意味を分ける。** 枠なしのリンクは別ページへの移動（`site-nav.css`）、枠で囲んだものはそのページの中の操作（`site-controls.css`）です。この対応を崩すと、利用者はどちらなのか見分けられなくなります。
- **切り替えUIは3種類だけ。** 排他的な切り替えは`.seg`、絞り込みは`.chips`、年のように値が多いものは`.control-field`の`<select>`です。新しい形を増やさないでください。
- **`font-size`は必ず`calc(Npx * var(--fs))`で書く。** px直書きにすると、その要素だけ「表示設定 → 文字サイズ」が効かなくなります。
- **太さは400と700の2段階だけ。** 800や900は、可変フォントのない環境（Windowsの游ゴシック、AndroidのNoto Sans JP）では700に丸められて区別が消えます。
- **角丸は3px。** 丸ピルの999pxだけが例外です。
- **本文中のリンクの下線を消さない。** 色だけでリンクを示すと、色の見分けがつきにくい人に伝わりません（WCAG 1.4.1）。`.seg`や`.chips`のように囲みで操作だと分かるものは例外です。

## 主なデータファイル

### 共通・人物

- `data/site.js` — 共通設定と年の一覧。各ページはこの`years`を見て年データを読み込みます。
- `data/members.js` / `data/former-members.js` — 現職・元職の区議名簿です。
- `data/politicians.js` — 現職・元職の都議、衆議、区長名簿です。
- `data/people.js` — 質問者と議員を紐付ける人物台帳で、表記揺れの名寄せにも使います。
- `data/speaker-members.js` — 会議録の発言者名（「安藤委員」）と議員IDの対応表です。自動生成で、議員ごとの年度索引も持ちます。

### 議会・行政

- `data/petitions.js` — 請願・陳情を受理番号で名寄せした自動生成台帳です。
- `data/petitions-official.js` — 公式ページから取得した付託委員会、受理年月日、議決結果です。
- `data/resolutions.js` — 公式「意見書・決議等」から取得した意見書、決議などです。
- `data/elections.js` — 品川区の選挙アーカイブデータです。
- `data/seimu.js` — 政務活動費の年度・会派・議員別公式資料です。
- `data/seijishikin.js` — 政治団体の収支報告書データです。
- `data/fiscal.js` — 予算・決算の年度別公式資料です。
- `data/gyosei.js` — 行政評価（事務事業評価・政策評価）の年度別公式資料です。

### ニュース・町会

- `data/news-items.js` — 自動収集したニュースです。
- `data/chokai.js` — 13地域センターの町会・自治会名と住所区域です。
- `data/chokai-boundaries.js` — 品川区「しながわMAP」の公式Shapeから変換した町会境界GeoJSONです。
- `data/chokai-profiles.js` — 連合会・しながわすまいるネットで公開されている町会長、連絡先、紹介、活動、ウェブサイト、SNSです。

### 年別データ

- `data/h13.js`〜`data/h29.js` — 平成13〜29年の会議、質問、答弁要約です。議案・請願陳情は未収録です。
- `data/h30.js`〜`data/r08.js`と各`-complete.js` — 平成30年〜令和8年の基礎データと全件表示用補足データです。
- `data/h13-committees.js`〜`data/r08-committees.js`と分割ファイル`-part-NN.js` — 年別の委員会質疑・答弁要約です。
- `data/minutes/<年>/<会議ID>.js` — 正式会議録の全文です。委員会1回・本会議1日につき1ファイルで、その会議の「会議録全文」を開いたときだけ読み込みます。
- `data/<年>-plenary-minutes.js` — 本会議の全文の目次と、質問者ごとの原文への入口です。年データと補足データを読み込んだあとに重ねます。

## 年データの読み込み

`data/site.js`の`years`は、会議録ページ（`kaigiroku.html`）と横断検索（`kensaku.html`）が年データを読み込むための共通一覧です。新しい年の追加方法は[データの更新方法](data-maintenance.md#過去年未来年の追加)を参照してください。

## 会議録全文の読み込み

委員会・本会議とも、要約や抜粋（索引）と全文は別の層に分かれています。

| 層 | ファイル | 読み込む単位 |
|---|---|---|
| 抜粋（委員会） | `data/<年>-committees-part-NN.js` | 年を選んだとき |
| 要約（本会議） | `data/<年>.js` / `<年>-complete.js` | 年を選んだとき |
| 全文の目次（本会議） | `data/<年>-plenary-minutes.js` | 年を選んだとき（数KB） |
| 全文 | `data/minutes/<年>/<会議ID>.js` | その会議の「会議録全文」を開いたとき |

全文は26年分で約470 MBあり、年単位でまとめて読み込むと1年約30 MBになって画面が開けません。委員会1回（平均約131 KB）・本会議1日（平均約119 KB）ずつに分け、読む意思表示があってから取りに行きます。

読み込みは`fetch()`ではなく`<script>`で行い、`window.SHINAGAWA_DB.registerMinutes()`へ登録します。`index.html`をダブルクリックして`file://`で開く使い方を残すためで、`fetch()`は`file://`ではCORSで止まります。ファイルの置き場所は会議IDから導けるため（`r06-20240515-19`→`data/minutes/r06/r06-20240515-19.js`）、対応表は持ちません。

委員会の抜粋は各質疑が`voiceIndex`（元の発言の位置、1始まり）を持ち、「原文を読む」から全文の該当発言（`#committee-<会議ID>-v0047`）へ移動できます。本会議は質問者ごとに、その議員が質問を始めた発言への入口（`#plenary-<会議ID>-v0008`）を持ちます。要約が見出しの言い換えで終わっていても、1手で原文に届くようにするためです。

会議IDの末尾で本会議（`r06-20240220-honkaigi`）と委員会（`r06-20240515-19`）を見分け、アンカーの接頭辞を切り替えます。設計の背景と容量の見積もりは[会議録全文の掲載設計](fulltext-minutes-plan.md)にあります。

## 議員ごとの質疑

本会議の`questions`は`memberId`を持ちますが、委員会の`exchanges[].speaker`は「安藤委員」「石田（ち）委員」のような姓＋役職の文字列だけで、議員IDがありません。議員ごとに質疑を横断するには、この文字列を議員IDに解決する必要があります。

**索引層に`memberId`は入れていません。** 入れると`data/<年>-committees-part-NN.js`約370本すべてが差分になり、容量も約4.8 MB増えます。代わりに対応表だけを`data/speaker-members.js`（32 KB）に出しています。

```js
speakerMembers["石田（し）委員"] = [
  ["2013-07-01", "2019-03-25", "x-ishida-shingo"],
  ["2023-05-26", "2025-06-09", "x-ishida-shingo"]
]
```

ある発言者名はある期間ずっと同じ1人に対応します（「田中委員」は2023年4月の区議選を境に切り替わるだけ）。26,434組の対応が285区間に畳めるのはこのためです。区間には終わりを持たせ、**実際に発言した日の外は答えません**。開始日だけだと最後の区間が未来永劫続き、落選して在職していない日にも議員IDを返してしまいます（石田しんごは2019〜2023年が落選期間）。

同じファイルに議員ごとの年度索引も入れています。`giin.html`はこれだけで「3,117件・16年度」と年度別の内訳を出せるので、年データ（1年6 MB）を読み込まずに済みます。

```js
memberQuestionIndex["hideo_ishida"] = { "h13": 45, "h14": 62, ... }
```

`kaigiroku.html`は`?member=<議員ID>&year=<年度ID>`を受け取り、その年の`exchanges`を`resolveSpeakerMember(speaker, dateIso)`で絞って並べます。本会議の`questions`（`memberId`つき）も同じ並びに混ぜ、日付の新しい順にします。選んだ質疑は出典URL付きのプロンプトになり、利用者自身の生成AIへ渡せます。サイトにAIは載せず、作るのはプロンプトの文字列までです。

対応表の作り方と検査は[データの更新方法](data-maintenance.md)にあります。

## リンクの種類と色

| 型 | 色 | 用途 |
|---|---|---|
| `official` | 青 | 公式資料・日程へのリンク |
| `video` | 赤 | インターネット中継の録画へのリンク |
| `minutes` | 緑 | 会議録検索システムの正式版へのリンク |
| `minutesDraft` | 緑 | 校正原稿PDFへのリンク |

`minutesDraft`の校正原稿PDFは、正式版公開後に公式サイトから削除される場合があるため、該当リンクがある場合は注意案内を表示します。

## スマートフォンとアクセシビリティ

- サイトの全14ページを対象に、幅320px以上でページ全体の横方向のはみ出しが出ないよう調整しています。
- 画面幅640px以下では、共通ナビゲーションの14リンクを「☰ メニュー」にまとめ、現在のページ名をボタンに表示します。
- 入力欄と選択欄は16px以上とし、iOSで操作時に画面が自動拡大しにくいようにしています。
- 選挙結果など横に長い表は、案内を表示したうえで表だけを横スクロールできるようにしています。
- ボタンとリンクには原則44px以上の操作領域を確保しています。
- 文字サイズ、高コントラスト、動きを減らす設定は全ページ共通で利用でき、端末内に保存します。
- パソコン向け表示では、折りたたみメニューは表示しません。
