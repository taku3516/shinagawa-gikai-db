# 質問・答弁要約の作成ルール

本会議の代表質問・一般質問（`qaSummaries`）と、委員会質疑（`committeeSessions[].topics[].exchanges`）
の要約を作るときの共通ルール。会議録を遡って実装するとき、新しい会議録から要約を足すときは、
必ずこのルールに従い、最後に**検査**を通してから公開する。

## いちばん大事なこと

読む人が知りたいのは **「何について質問したか」「何について答弁したか」** の2つ。
要約がこれを伝えられていなければ、短くても長くても失敗している。

そのため次の2つを絶対に守る。

1. **文の途中で切らない。** 文字数の上限に当たったら、その手前の**文の区切りまで戻す**。
   語の途中で切って「…」を付けると、何について述べたのかが読み取れなくなる
2. **「答弁が無い」と「答弁を拾えなかった」を混ぜない。** 意見・要望のように答弁を
   求めていない発言と、答弁があるはずなのに拾えていない発言は、別の文言で書き分ける

## 判定と整形は1か所に集約する

ルールを生成・修復・検査の3か所に書くと必ずずれる。判定と整形はすべて
**`scripts/qa_summary.py`** に置き、次の3つがこれを読む。

| スクリプト | 役割 |
|---|---|
| `scripts/prepare_committees.py` | 委員会質疑を会議録から**生成**する |
| `scripts/build_heisei_year.py` | 本会議（平成年）を会議録から**生成**する |
| `scripts/build_from_minutes.py` | 質問者ページが無い年を会議録本文から**生成**する |
| `scripts/summarize_history.py` | 過去年の質問・答弁要約を**生成**する |
| `scripts/repair_qa_summaries.py` | すでに書き出したデータを**修復**する |
| `scripts/check_qa_summaries.py` | 公開前・変更時に**検査**する |

新しく要約を作るスクリプトを書くときも、切り詰め・語尾の変換・答弁なしの文言は
自分で書かずに `qa_summary` の関数を使う。

```python
import qa_summary as qa

question = qa.normalize_question(qa.finish(text, qa.QUESTION_LIMIT))
answer = qa.strip_answer_lead(qa.finish(text, qa.ANSWER_LIMIT)) or qa.no_answer_text(kind)
```

## スキーマ

本会議は質問エントリ（`questions[]`）に `qaSummaries` を持たせる。

```json
{ "title": "発言項目名（例: 防災について）",
  "question": "質問の要約（1〜2文・完結した文）",
  "answer": "答弁の要約（1〜2文・完結した文）" }
```

委員会は議題（`topics[]`）の下に `exchanges[]` を持たせる。`kind` は
質問／質問・要望／確認／提案／意見のいずれか。**答弁が無いときの文言は `kind` で決まる**ので、
`kind` を空にしない。

## 文体ルール

1. **必ず完結した文にする**。文末は「。」で終わる。途中で切れた抜粋を置かない
   - 上限に当たったら文の区切りまで戻す（`qa.finish`）
   - 語尾を付けてから文字数で切ると語尾自体が欠ける。**長さを整えてから語尾を付ける**
2. **質問は間接話法**で書く。議員の発言をそのまま接ぎ木しない
   - NG: 「議員は、〜についてお聞かせください。」（一人称の命令形が残る）
   - OK: 「議員は、〜の説明を求めました。」「〜の検討を求めました。」
   - 変換表: お聞かせください→説明を求めました ／ お答えください→答えるよう求めました ／
     お示しください→示すよう求めました ／ ご見解を伺います→見解を尋ねました ／
     検討いただきたい→検討を求めました ／ すべきです→べきだと主張しました
3. **答弁は「区側は、」で始め、です・ます体**で書く
   - 「私からは」「お答えいたします」などの前置きだけの文は採用しない
   - **「区側は、まず初めに、」のような中身の無い前置きは落とす**（`qa.strip_answer_lead`）。
     限られた字数を中身の無い語で使わない
4. **長さの上限**: 質問190字・答弁240字（`qa.QUESTION_LIMIT` / `qa.ANSWER_LIMIT`）
5. **重複表現の禁止**: 「「〜について」について」のような二重表現を作らない
   - titleが「〜について」で終わるならその部分を除いてから定型文に当てはめる
6. **文頭・語頭の断片禁止**: 「ィーゼル車」のように語の先頭が欠けた抜粋を置かない
7. **短い答弁はそのままでよい**。「そのとおりです。」のような答弁は、画面では質問の
   すぐ下に並ぶため意味が通る。無理に長くしない

## 答弁が取れないときの文言

推測で答弁を作らない。次のどちらかを使う（`qa.no_answer_text(kind)` が選ぶ）。

| 発言の種類 | 文言 |
|---|---|
| 意見・提案 | 答弁を求める発言ではないため、これに対する答弁はありません。 |
| 質問・確認・要望 | この発言に対する答弁を会議録から特定できませんでした。会議録の全文をご確認ください。 |

質問の内容が取れないときの定型文は
「「{title}」について、現状の認識と区の対応を質問しました。」。
これは**取り直しが必要な印**であり、望ましい状態ではない。検査で件数が出る。

## 出典と免責（必須）

- 各質問エントリの `links` に、該当日の会議録（`Template=document&Id=N`）または
  会議録検索へのリンクを必ず含める
- 表示側の免責「※質問・答弁の要点を本サイトで要約しています。正確な発言は公式の
  会議録をご確認ください。」が出ることを確認する

## 生成手順（会議録からの機械抽出）

1. 会議録本文から発言スパンを切り出す（`〔○○君登壇〕`マーカー。役職者
   （区長・教育長・次長・部長・議長・委員長・監査・室長・所長・管理者）は答弁側）
2. 発言者ヘッダ（`N:◯区長（…）`）は必ず除去してから文抽出する
3. 質問がある日だけを対象にする（議事日程に「質問」の記載がある日。
   最終日の委員長報告・討論の登壇者を質問者に混ぜない）
4. テーマは質問文の「初めに／次に／第一に／まず初めは」等の列挙から抽出
5. 答弁の照合はテーマの先頭8字→6字→4字→末尾5字の順で試す。
   前置き文（60字未満で「お答え」を含む文）はスキップして次の実質文を採る
6. 要約の整形は `qa_summary` の関数に通す（自前で切らない）

## 検査（公開前に必ず実行）

```bash
python3 scripts/check_qa_summaries.py           # 件数だけ
python3 scripts/check_qa_summaries.py --details # 問題のある要約も表示
```

検査は2種類に分かれる。

- **要修正** — 空・文の途中で切れている・古い文言のまま・二重について・一人称・
  語頭の欠落・字数超過。機械的に直せるので**0件でなければならない**。
  1件でもあると終了コード1になり、GitHub Actions（`.github/workflows/check-qa-summaries.yml`）が失敗する
- **要改善** — 「〜についてお伺いします」だけの質問、定型文のまま、短すぎる質問。
  会議録から取り直さないと直らない。件数を出すだけで失敗にはしない。
  再生成のたびに減らしていく

すでに書き出したデータに要修正が出た場合は、まず次を試す。

```bash
python3 scripts/repair_qa_summaries.py           # 何件直るかを確認
python3 scripts/repair_qa_summaries.py --write   # 実際に直す
```

修復できるのは「完結した文まで戻す」「前置きを落とす」「語尾を整える」までで、
切り落とされた文そのものは戻らない。それ以上は会議録からの再生成が必要になる。
