# 公開前の残作業

## 公式資料の追加照合

- 議案別の提出・上程・委員会付託・審査・表決の日付と例外経路を追加する。番号のない議案には公式番号を確認できた時点で旧詳細リンクを維持する。
- 表決PDFを会期単位で追加し、列位置、議員ID、当時の会派、議長の不参加、退席・欠席等を照合する。
- 事業カルテの事業を増やし、年度ごとの予算・決算・財源・執行率・評価の資料を紐付ける。一致の根拠がある案件だけを結ぶ。
- 請願の事後対応を引き続き区議会だよりと区の公表資料から確認する。
- 個別の政治資金・政務活動費の支出明細は、再配布範囲、領収書の公表範囲、金額を照合する。政治資金と政務活動費の集計を混在させない。
- 会期予定、事業カルテ、表決の入力はまだ手作業。既存の定期更新はそのまま使用し、追加の自動収集は公式サイトごとの利用条件と日程・表の変化を確認してから導入する。
- 事業・地域・議員の関係は、確認された関係と語句検索の候補を明確に表示し続ける。

## 運用の決定が必要な接続

- サイト独自の意見募集は、運営主体・保持期間・公開方針の決定、投稿先、連投対策、公開前確認と集計の基盤が必要。ニュースのFirestoreには公開投稿権限を付与していない。
- 誤り報告は連絡先または受付フォームが確定した段階で接続する。現在は入力をテキストに保存できる。
- AI質問のサーバー側は `scripts/civic_answer.py` の検索器・モデル選択器をHTTPに接続する。JSON要求は `question`、応答は `summary` と `evidence`（ID、資料名、URL、該当箇所、期間、登録済みの抜粋）。モデルに任せるのは許可された候補IDの選択。公開時はCORSをサイトの配信元に限定し、共有レート制限・費用上限・タイムアウト・認証情報をサーバー側に設定する。実運用ではプロセス内の上限だけに依存しない。フロントエンドの接続先 `SHINAGAWA_CIVIC_ANSWER_URL` は公開設定で与える。
- 公式資料の追加照合後、テーマや大きい文字でのキーボード操作、複数ブラウザとスクリーンリーダーでWCAG適合を検証する。
- ローカルコミット、リモート反映、PR作成、公開検証は承認後。GitHub Pagesの公開前にCIを通し、対象コミットのレビューと未解決スレッドを確認する。
