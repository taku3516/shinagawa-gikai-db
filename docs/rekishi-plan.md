# 「品川の歴史」実装計画

品川区議会DBに、品川区の地域史を体系的にたどれるコンテンツ群を追加するための計画です。
既存の議会情報・町会区域マップ・ニュース・イベント・横断検索とは独立した機能として作ります。

- 対象: 原始・古代〜現代の品川区域の歴史（出来事・場所・人物・地名）
- 方針: 出典を確認できた情報だけを公開し、確認できなかったものは保留データとして公開しない
- 作成日: 2026-11-19

---

## 1. 調査で分かったこと

### 1-1. 既存サイトの作り

| 項目 | 現状 |
|---|---|
| 構成 | HTML / CSS / JavaScript のみ。フレームワーク・ビルド不要 |
| ページ | 15ページすべてがリポジトリ直下に平らに置かれている |
| データ | `data/*.js` が `window.SHINAGAWA_DB` に登録するスクリプト形式。`file://` でも動く |
| 共通CSS | `site-theme.css` → `base` → `nav` → `controls` → `mobile` → `a11y` → ページ個別`<style>` の順 |
| 地図 | `chokai-map.html` が Leaflet 1.9.4（unpkg）＋ OpenStreetMap |
| 公開 | `scripts/build_pages.py` が **gitで管理されている全ファイルから `docs/` と `scripts/` を除いて** `_site` に写す |
| 容量 | 公開対象 650MB（うち会議録全文 493MB）／GitHub Pages の上限は 1GB |

**公開の仕組みの帰結**: 新しいページとデータを足すだけで自動的に公開対象に入ります。`build_pages.py` の変更は不要です。

### 1-2. ディレクトリ名を `history/` にしない理由

指示では `history/index.html` などが提案されていましたが、調査の結果、**リポジトリ直下に `rekishi-` を付けた平らなファイル名**にします。理由は4つです。

1. **現在地の下線が出なくなる。** `site-nav.js` の `isCurrent()` は、URLの最後の部分（`timeline.html`）とナビに書かれた URL（`history/timeline.html`）を文字列として比較します。サブディレクトリに置くと一致せず、「いまどのページを見ているか」の表示が消えます。
2. **サイト内リンクが壊れる。** `history/` の中から `kaigi.html` と書くと `history/kaigi.html` を指します。既存15ページはすべて「直下にいる」前提で相対リンクを書いています。
3. **CSS・データの読み込みパスが二重基準になる。** サブディレクトリでは `../site-theme.css`、`../data/site.js` と書く必要があり、ページによって書き方が変わります。
4. **`history` はこのリポジトリでは別の意味で使われている。** `docs/history-expansion.md`、`scripts/prepare_history.py` などは「過去年（平成13年〜）の議会データ」を指します。同じ語を地域史に使うと、最も間違えやすいところで紛らわしくなります。

既存のファイル名も `kaigiroku` `seigan` `ikensho` `senkyo-shushi` `yosan-kessan` `chokai-map` と日本語のローマ字表記で平らに並んでいるため、`rekishi-` 接頭辞はこの並びに素直に収まります。

### 1-4. たどり着けなかった出典（2026-11-20 調査）

地名の由来を集めようとして、次の3つを当たりましたが、いずれも現在は使えません。
**計画どおりに進まなかった記録として残します。**

| 出典 | 状況 |
|---|---|
| ADEAC「住居表示新旧対照表」 | トップのメニューには載っているが、**資料グループ6つ（区の刊行物／区広報紙／地域ニュース／浮世絵／映像／統計）に含まれず**、`/top/topg/10_address/` も `/kikan_fix_html/.../10_residence/` も「表示できるファイルがありません」を返す |
| 広報しながわ 連載「その名の由来をひもとけば」 | **PDFが404**。2026年10月20日のサイトリニューアルで消滅し、転送も無い。公式サイトのバックナンバーは令和8年分のみ |
| レファレンス協同データベース（国立国会図書館） | 間を空けて2回とも**504**で応答しない |

ADEAC全体が ASP.NET の `__doPostBack`（POST＋viewstate）で動いており、GETでは
一覧も全文検索もたどれません。viewstateを扱えば取れる可能性はありますが、
壊れやすいうえ、利用規定の「プログラムを利用した取得」の線に近づくため見送りました。

そのため地名の由来は、**すでに出典として使っている品川区公式「指定文化財」の解説**から
拾えるものだけを収録しています。128件の詳細ページを読み、由来が分かるもの4件と、
公式資料に現れる旧村名・旧宿名・古道14件を収めました。上記の出典が開いたときに
増やせるよう、データ構造と画面は先に用意してあります。

### 1-5. 資料源の開拓（2026-11-20 調査）

収録を増やすために、品川区公式とADEAC以外の資料源を実際に叩いて確かめました。
**使えるものが2つ見つかり、5つは行き止まりでした。**

#### 使えるもの

| 資料源 | 入口 | 分かったこと |
|---|---|---|
| **国立国会図書館サーチAPI** | `https://ndlsearch.ndl.go.jp/api/opensearch?any=…` | 鍵不要で動く。「品川区史」で6,142件。**連続して叩くと429**が返るので間隔が要る |
| **文化遺産オンライン（文化庁）の個別ページ** | `https://online.bunka.go.jp/heritages/detail/<id>` | **curlで読める**（サーバー側で描画）。題名・解説・時代・所蔵・法量が入っている |

文化遺産オンラインは、**一覧だけがJavaScript**で描かれます
（`/heritages/search/result?region=13109` で区内80件）。一覧はブラウザで取り、
個別ページはcurlで取る、という組み合わせになります。

#### 行き止まり

| 資料源 | 状況 |
|---|---|
| ADEAC「住居表示新旧対照表」 | 資料グループ6つに含まれず、URLは「表示できるファイルがありません」 |
| レファレンス協同データベース API | **404**（以前504と記録したが、一時的な不調ではなくAPIの住所が変わった可能性） |
| 国指定文化財等データベース | ドメインは生きているが、試した検索URLはいずれも404。正しい入口が分からない |
| 文化財総覧WebGIS（奈良文化財研究所） | トップが1.4KBのJavaScriptの殻。公開データの入口を見つけられず |
| 東京都の文化財データベース | 試したホスト名（tokyo-bunkazai.jp ほか）はいずれも存在しない |
| 東京都オープンデータカタログ | robots.txt が403。ブラウザ以外を弾いている可能性 |

**深追いはしていません。** 行き止まりの5つは、正しい入口が別にある可能性が
残っています。時間をかければ見つかるかもしれませんが、見つかる保証のない
探索に時間を使うより、使えると分かった2つから進めるほうが確実です。

#### 次に手をつけるなら

1. **文化遺産オンライン** — いま解説を持っていない都・国指定の30件に説明を付けられる見込み
2. **国立国会図書館サーチ** — 原始・古代の資料を特定できる見込み。ただし**全文が読めるかは未確認**で、
   読めなければ書誌情報（この資料に載っている、という案内）までにとどまる

### 3-2. 1件の項目

```js
{
  id: "ev-1872-shinagawa-station",      // 種別接頭辞つきの安定ID
  name: "品川駅開業",
  kana: "しながわえきかいぎょう",
  summary: "一文の概要",
  description: "詳細説明（こちらの言葉で書く）",
  year: 1872, yearEnd: null,            // 不明なら null
  yearText: "明治5年5月",               // 表示用。確定できないときは「江戸時代初期」など
  era: "meiji",                          // 時代区分ID
  areas: ["shinagawa"],                  // 地区ID（複数可）
  categories: ["transport"],
  lat: 35.628471, lng: 139.738760,       // 地点のみ
  locationKind: "current",               // current / former / approximate
  locationNote: "開業時の位置は現在の港区高輪",
  relatedPeople: ["pe-..."], relatedPlaces: ["pl-..."], relatedEvents: ["ev-..."],
  certainty: "fact",                     // fact / tradition / popular / estimate
  variants: [                            // 資料で記述が異なる場合
    { claim: "…とする説", ref: "shinagawa-shishi-tsushi-jo", locator: "上巻 第4章 p.233" }
  ],
  sources: [{ ref: "sgw-bunkazai", locator: "品川地区 建造物 第1号" }],
  verifiedAt: "2026-11-20"
}
```

### 3-3. 重複を作らない4つの約束

1. **出典は台帳に1回だけ書く。** `data/rekishi.js` の `sources` に資料名・発行者・URL・ライセンスをまとめ、各項目は `ref` と `locator`（該当箇所）だけを持ちます。URLの無い出典は破線のpillで示し、押せないことを線の種類で伝えます（既存の出典表示の約束）。
2. **関連は片側にだけ書く。** 出来事が「関連する場所」を持ち、場所の側は**画面を開いたときに逆引き索引を組み立てます**。同じ関係を2か所に書かないので、片方だけ直して食い違う事故が起きません。
3. **地域の解説は `rekishi-areas.js` にだけ置く。** 地域ページも地図のポップアップも、同じ1件を参照します。
4. **保留データは公開ファイルに入れない。** 出典を確認できなかった項目は `scripts/out/rekishi/pending.json`（git管理外）に残し、確認が取れてから公開ファイルへ移します。

### 3-4. 正確性の扱い

- **確実性を4段階で区別**: `fact`（出典で確認できた事実）／`tradition`（伝承）／`popular`（俗説）／`estimate`（推定）。画面では色ではなく**語**で示します（色だけに頼ると見分けられない人に伝わらないため）。
- **年代が不明なものは確定させない**: `year` を `null` のままにし、`yearText` に「江戸時代初期」と書いて、時代区分で並べます。
- **資料同士で記述が違うときは両方載せる**: `variants` に、説ごとに出典と該当箇所を付けて並べます。地名の由来の複数説も同じ仕組みです。

## 4. 画面の設計

### 共通

- 既存の共通CSS6本をそのまま読み込み、ページ個別の `<style>` は最後に置きます。
- `font-size` は必ず `calc(Npx * var(--fs))`。太さは400と700のみ。角丸3px（丸ピルのみ999px）。本文中のリンクの下線は消さない。
- 切り替えUIは既存の3種類だけを使います（排他的な切り替え `.seg`、絞り込み `.chips`、値が多いもの `<select>`）。新しい形は増やしません。
- 枠なし＝別ページへの移動、枠あり＝そのページ内の操作、という既存の対応を守ります。

### 歴史年表（`rekishi-nenpyo.html`）

- 年代順表示、時代・地域・カテゴリでの絞り込み、キーワード検索。
- 1件を開くと詳細説明・関連する場所／人物／地名へのリンク・出典。
- 時代区分を見出しにした折りたたみ（既存 `ikensho.html` の年ごと折りたたみと同じ作り）。
- 将来の日本史・東京都史との比較に備え、`scope: "shinagawa" | "tokyo" | "japan"` を最初から持たせます。

### 歴史マップ（`rekishi-map.html`）

- Leaflet 1.9.4（既存と同じ版）。背景は OpenStreetMap と地理院タイル（淡色）を切り替え。
- 時代別・カテゴリ別・地域別の表示切り替え。
- **現存する地点と、現在は無い施設をマーカーで区別**し、ポップアップに「当時の位置」「現在の地名での位置」を明記します。混同させないためです。
- 地点をクリックすると詳細・関連人物・関連出来事・出典を表示。
- 数百〜数千点を想定し、まずは外部ライブラリを増やさずズーム段階で間引きます。

### 古地図・今昔比較（`rekishi-kochizu.html`）

- **古地図の画像はこのサイトに置きません。** 地理院タイルの年代別空中写真（1945-50／1961-64／1974-78…）を重ね、透明度スライダーで比較します。容量（Pages の残り約350MB）と著作権の両方を避けられます。
- 年代の切り替え、地域別表示、関連する史跡の重ね合わせ。
- 出典として「国土地理院」を常時表示します。

## 5. 性能・アクセシビリティ・テスト

- 年表ページは `rekishi-events.js` だけ、地図ページは `rekishi-places.js` だけを読み込みます。全部を1本にまとめません。
- 件数が増えたら時代別分割へ移行できるよう、ファイル一覧を `data/rekishi.js` に持たせます（会議録全文で実証済みのやり方）。
- 全文検索ライブラリ（Pagefind）は、索引が元データより大きくなるため使いません。既存ページと同じ正規化済み文字列の部分一致で検索します。
- 幅320px以上で横はみ出しが出ないこと、操作領域44px以上、入力欄16px以上を守ります。
- キーボード操作、`aria-current`、見出し階層、色以外の手がかりを確認します。
- 自動テスト: データの整合（IDの重複、壊れた相互リンク、出典の無い項目、緯度経度が品川区の範囲内か）を `scripts/test_rekishi_data.py` で検査し、GitHub Actions に組み込みます。
- 回帰テスト: 既存15ページが壊れていないことを確認します（共通ナビに1群足すため、全ページが影響を受けます）。

## 7. 確認が必要な事項

ADEACの本文を転載せず事実のみを記載する方針のため、**著作物の利用許諾は不要**です。有料サービスの契約、外部サービスへの新規登録、個人情報の扱いも発生しません。

承認をお願いしたいのは次の1点です。

- **確認事項**: この実装計画（ページ構成・データ設計・進め方）で着手してよいか
